# Jev 自媒体系列：让 AI 判断，让代码掌控流程

本目录包含 **10 篇完整中文图文稿、10 张正文配图、5 组可运行离线案例**，以及选题与发布规划。面向关注 AI 应用的开发者、独立开发者和有技术基础的产品经理，按微信公众号／技术专栏长文组织。2026-10-14 增补 `tutorial/` 实战线；现已生成配图并插入各篇正文。

[发布摘要与转发文案](发布素材清单.md) · [全部配图预览](illustrations/jev-series/README.md) · [配图大纲](illustrations/jev-series/outline.md) · [案例说明](examples/README.md)

依据仓库 [tutorial-official](../tutorial-official/README.md) 整理，并于 **2026-10-13** 在线重点核对 TypeSafe 官方介绍、API、模型、原语、置信度、编码智能体与已知局限页面。这里是个人解读，不是 TypeSafe 官方发布物；本地 `tutorial-official` 也属于官方文档的中文学习笔记。

## 为什么规划为 10 篇

前六篇按读者会依次遇到的六个问题组织：它是什么、如何调用、如何问对、如何行动、如何接入 Agent、如何评估上线。后四篇补完整业务案例，依次完成客服分诊、自媒体赞助筛选、Agent 状态与文件判断、批量评测。原教程作为查阅材料，文章按业务任务组织，避免重复翻译章节。

以“客服工单分流”贯穿前四篇，第五篇扩展到编码智能体，第六篇建立评估方法；第七至十篇用输入、问题、策略结果和边界案例落实这些方法。每篇可以独立阅读，实战篇可直接配合案例运行。

## 实例入口

从仓库根目录执行，一次运行五组离线案例：

```bash
python3 articles-jev/examples/run_examples.py
```

详见 [案例说明](examples/README.md)。无需密钥、无需额外依赖；脚本不联网、不发送邮件、不执行 Agent 操作。可以导出工单和赞助案例的完整请求 JSON，也可以导入自己的 CSV 计算指标。配套的合成预测只解释策略和计算，不测模型能力。

## 对原教程的校正与保留边界

| 主题 | 新文章采用的口径 |
|---|---|
| 并发估算 | 稳定负载下近似请求速率 × 平均延迟；并发与限速分开，修正 tutorial 第 08 章公式 |
| 上下文 | 区分官方总量与 state + 最长问题双限制；仓库约 60k state 预算不能直接照搬 |
| 接入服务 | 区分地址、密钥、模型名与配置；不沿用“三者请求完全一样、只换地址和密钥”的说法 |
| 内置后端 | 源码支持 mock/typesafe/openrouter；没有名为 jev-ai.pro 的内置 provider，不能只设置该名字 |
| 成本账本 | 通用客户端与 Level 10 演示账本行为不同，缺失费用不直接解释为免费 |
| 文件筛选 | 新例明确保留失败项，候选溢出要求分组；不把新增策略写成原代码已有能力 |
| 中文 | 英文选项键是代码约定，不宣传能保证中文效果；不使用固定字符/token 比例保证容量 |
| 第三方服务 | 2026-10-14 核对其接口文档；模型目录、积分、性能宣传未做完整核验，不照搬为事实 |

## 发布口径

- 文中工单、概率、阈值、成本输入量和评测表均明确标记为自编示例或假设。此次没有调用收费推理接口，没有产生中文准确率或延迟实测。
- 第二篇提供完整 HTTP 示例；其他代码明确标注为局部逻辑或离线演示。文章中的业务设计是作者建议，不是官方推荐阈值。
- API 以 `api.typesafe.ai` 为准。第三方仓库的 Agent 扩展单独标注，不把 OpenRouter、转售站和官方直连接口混写。
- 价格与模型版本是核对日快照。发布时重新查看 [Models](https://docs.typesafe.ai/models)，不要把旧版限制写成永久性质。
- 使用各篇一级标题作为文章标题，正文第一段可用作摘要；末尾系列导航发布时替换为平台链接。来源链接建议保留，供读者核对。
